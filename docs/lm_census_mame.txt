Limenko sprite census in MAME 0.289 (limenko.cpp 96962b96c89): scripts/lm_census.py, scripts/mame/lm_census.lua.

Runs, each set, 1800 frames counted:
  attract: python scripts/lm_census.py <set> --skip 600 --frames 1800
  play:    python scripts/lm_census.py <set> --coin 600 --skip 1500 --frames 1800 --tag _play
At each draw command the script walks the list MAME draws (the bank selected after the toggle, entries 0..the
count latched at the previous command, enabled and inside the graphics region) without drawing. Per command:
  count         the latched count (entries walked = count + 1)
  enabled       entries with word 0 bit 31 set that pass MAME's bounds check
  visible       of those, sprites with a pixel inside 384 x 240 (positions wrap at 512)
  pix_all       sum of w * h: what MAME draws into its 512 x 512 bitmap
  pix_vis       of those, pixels inside 384 x 240
  maxline_vis   the most visible sprite pixels on one line
  maxline_full  on one visible line, the summed full widths of the sprites crossing it (what a line renderer
                fetches, 8bpp: bytes)
  maxspr_line   the most sprites crossing one visible line
  other         enabled entries in the bank not drawn
Per frame: the commands, and the CPU's writes into the bank last drawn and into the other bank.

Summary
- One draw command in every frame of every run (21,600 frames), on line 0 after the interrupt.
- Worst line: 1536 bytes of sprite rows (sb2003 attract, at most 24 sprites on a line); the most sprites on a
  line 59, at most 1264 bytes (sb2003 play). Worst command: 266 sprites (sb2003 play); 258,624 pixels drawn
  and 202,007 visible (sb2003 attract).
- After a command, dynabomb, sb2003, sb2003a, hrthouse and spotty write the next list into the bank MAME has
  just drawn (the bank IN2 reports); legendoh writes the other bank. So in five sets MAME draws the list
  written in the frame before the command's, and the drawn bank is rewritten from line 0 (dynabomb, spotty),
  2 (sb2003 attract), 4 (sb2003 play), 5 (hrthouse play) or 8 (hrthouse attract) after it
  (debug/wtiming/<set>.txt). MAME draws at the command, so it shows no conflict; a chip drawing over time
  would read a bank being rewritten. Unresolved; the core follows MAME and must copy the list before the
  first of those writes.
